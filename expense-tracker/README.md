# Учёт личных трат (Go, этапы 1–7)

Серверное веб-приложение на `net/http` + `html/template` + SQLite.

## Запуск
Требуется Go 1.22+ (нужны шаблоны маршрутов `GET /expenses/{id}`). CGO не нужен.

```bash
go mod tidy        # скачает зависимости и создаст go.sum
go run .           # или: go run ./cmd/server
```
Откройте http://localhost:8080. Сервер нужно запускать **из корня проекта**:
пути к шаблонам и миграциям относительные.

Необязательные переменные окружения: `PORT` (8080), `DB_PATH` (expenses.db),
`TEMPLATES_DIR`, `STATIC_DIR`, `MIGRATIONS_DIR`, `COOKIE_SECURE` (false),
`ENABLE_DEBUG_ROUTES` (true, включает маршрут /debug/panic).

| GET | `/` | главная (приветствие) |

| GET | `/stats` | страница с графиками (нужен вход) |

- **Этап 2/3:** добавьте трату. После отправки формы будет redirect (303), и F5 не отправит её повторно. Перезапустите сервер: данные сохранятся в `expenses.db`.
- **Этап 4:** проверьте фильтры в любых комбинациях: только категория, только даты, всё вместе, ничего.
- **Этап 5:** зарегистрируйте двух пользователей. Каждый видит только свои траты. Чужой `/expenses/{id}/edit` отдаёт 404.
- **Этап 7:** введите сумму `-100`, `abc`, пустое описание или дату в будущем. Форма покажется снова, с введёнными данными и текстом ошибки.

## Архитектура
- `main.go`, `cmd/server` — точки входа (`go run .` по этапу 1, `cmd/` по этапу 2).
- `internal/app` — сборка зависимостей и запуск сервера (graceful shutdown).
- `internal/handlers` — HTTP-обработчики, **без SQL**.
- `internal/repository` — **весь SQL** (запросы с плейсхолдерами `?`).
- `internal/forms` — серверная валидация.
- `internal/middleware` — логирование, recover, авторизация.
- `internal/render` — шаблоны: `layout.html` + страница (`define`/`block`/`template`).
- `migrations/` — SQL-миграции. Применяются при старте, версии хранятся в `schema_migrations`.

Цепочка middleware: `Logging → Recover → LoadUser → ServeMux → RequireAuth → обработчик`.
Logging стоит снаружи, поэтому видит итоговый статус, в том числе 500 после паники.
Recover ловит панику во всём, что внутри него.
LoadUser кладёт пользователя в `context`, RequireAuth пускает дальше только авторизованных.

## Отчёт по этапу 1: путь запроса
1. ОС принимает TCP-соединение. `http.Server` (`ListenAndServe`) читает и разбирает HTTP-запрос в `*http.Request`: метод, URL, заголовки, тело.
2. Сервер вызывает корневой `Handler`, то есть цепочку middleware, а затем `http.ServeMux`.
3. ServeMux сопоставляет метод и путь с шаблонами маршрутов и вызывает обработчик. Если ничего не подошло, вызывается обработчик 404.
4. Обработчик пишет ответ через `http.ResponseWriter`: заголовки (`Header().Set`), статус (`WriteHeader`), тело (`Write`).
5. Сервер отправляет ответ клиенту, а соединение либо остаётся открытым (keep-alive), либо закрывается.

Если обработчик ничего не запишет в ResponseWriter, клиент получит `200 OK` с пустым телом.

## Шпаргалка к защите
- **GET и POST.** GET читает данные: безопасен, повторяем, параметры видны в URL (фильтры). POST меняет данные: создание, удаление, вход.
- **html/template.** Экранирует данные с учётом контекста (HTML, атрибут, URL, JS). Описание `<script>` выведется как текст, а не выполнится (защита от XSS).
- **PRG.** После POST отправляется redirect `303 See Other`, браузер делает GET. Поэтому F5 не повторяет отправку формы.
- **SQL-инъекции.** Значения передаются отдельно от текста запроса (`?`), и драйвер никогда не исполняет их как SQL. `fmt.Sprintf` в SQL позволил бы ввести `' OR 1=1 --`.
- **N+1.** Если сначала выбрать траты, а потом делать по запросу на категорию каждой строки, получится N+1 запросов. `LEFT JOIN` даёт всё одним запросом.
- **Сессии.** Если не проверять `expires_at`, украденная cookie работала бы вечно. Здесь срок проверяется в SQL, а просроченные сессии удаляются.
- **bcrypt.** Медленный хэш с солью. Утечка БД не раскрывает пароли.
- **SUM/GROUP BY в БД.** Клиенту передаётся несколько строк вместо всех записей, база использует индексы, и в Go меньше кода и памяти.
- **recover.** `defer` + `recover()` в middleware превращает панику в ответ 500. Сервер продолжает работать.
